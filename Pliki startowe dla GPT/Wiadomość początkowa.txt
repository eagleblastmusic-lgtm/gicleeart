## Integracja ZIP (v40)

Lokalne pliki startowe i `integracjagpt` używają **v40** (`giclee_cursor_architect_knowledge_v40.zip`).

Przycisk **„Skopiuj .zip”** w Oknie rozmowy generuje aktualną paczkę v40.

---

Przeczytaj wszystkie pliki wiedzy co do jednego.

Najpierw ustal:

1. główny plik Instructions: `GICLEE_CURSOR_ARCHITECT_INSTRUCTIONS_COMPACT_v40.md`
2. aktualny `CURRENT_APP_STATE.md` — § Current repository state (per repo)
3. roadmapę: `GICLEE_PROJECT_REFACTOR_ROADMAP_v2.md`
4. pipeline: `GICLEE_AUTONOMOUS_ENGINEERING_PIPELINE_v1.md`
5. dostępne tryby analityczne
6. repozytoria wymagane dla zadania
7. aktualny stan GitHub przez connector — **przed pracą weryfikuj GitHub**
8. różnice między checkpointem a bieżącym kodem

Zasady:

- lokalne pliki w `C:\Strona\pusty\Pliki startowe dla GPT` są źródłem prawdy dla instrukcji
- GitHub jest źródłem prawdy dla bieżącego kodu i stanu branchy
- **nie opieraj się na SHA zapisanym w tej wiadomości jako trwałej prawdzie** — SHA w `CURRENT_APP_STATE.md` są checkpointem do weryfikacji
- ZIP jest wyłącznie snapshotem
- dla prywatnych repo używaj GitHub connectora
- nie używaj publicznych URL ani `raw.githubusercontent.com`
- nie generuj ZIP-a bez osobnego polecenia
- nie wykonuj deployu ani Shopify mutation bez jawnej zgody
- nie rozpoczynaj implementacji przed ustaleniem zakresu, kontraktu, testów i guardraili
- po failure CI czytaj artifacty, nie wykonuj blind rerun
- merge wykonuj dopiero po finalnym review, exact head SHA **i jawnej autoryzacji użytkownika** — zielone CI samo nie autoryzuje merge

Po odczytaniu wiedzy potwierdź:

- główny plik Instructions (v40)
- aktualny checkpoint per repo (`CURRENT_APP_STATE.md`)
- aktualny GitHub master/main (jeśli zweryfikowany)
- otwarte lub oczekujące PR-y
- obecny następny etap per tor (nazwa toru + data weryfikacji)
- najważniejsze guardraile
- status integracji ZIP oraz ewentualne rozbieżności manifestu

Następnie czekaj na konkretne zadanie.
