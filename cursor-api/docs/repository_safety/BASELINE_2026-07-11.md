## Existing GicleeApp push safeguards

The current workflow already includes:

- explicit `git add -- <paths>` rather than `git add -A`;
- staging remote validation;
- ff-only pull behavior;
- secret scanning of changed candidates;
- runtime denylist and protected review-only files;
- staged-path verification before commit.

Identified gaps:

1. source synchronization scans the complete filesystem tree and filters it through distributed denylist rules;
2. push audit primarily evaluates current working-tree changes rather than all tracked files;
3. policy is duplicated between `.gitignore`, configuration constants and tests;
4. snapshot lacks a deterministic source tree hash and complete skipped-path/security manifest;
5. local runtime files may already be tracked and therefore invisible to a changed-file-only gate.
